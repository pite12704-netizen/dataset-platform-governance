# 自动需求记忆与检索证据过滤

2026-11-05更新。修正“找老人却展示全部候选”及新增检索绕过旧历史链路的问题。

## 用户可见行为

- 无需点击按钮，连续追问自动继承同一会话的检索需求。
- “找老人的数据 → 只要图片 → 还要戴帽子 → 不要求帽子了”分别更新目标、模态和条件。
- “重新找儿童数据”开始新需求；不同账号、不同会话不共享需求。
- 每轮可展开“本轮自动记住的需求”，查看实际查询、模态、排除项及已折叠轮数。
- “固定上下文线索”改为可选“收藏结果”，新增检索结果可收藏，收藏不是连续对话的前提。
- 元数据没有明确提及老人等目标时不展示为条件匹配，明确说明目录依据不足；不会推断原图没有老人。
- 目录描述提及也不等于图片已经人工核验。服饰/年龄标签真实性仍需识别及复核。

## 后端如何调用

`assistant.prepare_chat → agent_query_memory.prepare → refine`
读取本人同一会话的最新成功检索状态；从用户消息更新需求，存入本轮AgentRun.outputs.query_memory。
已有旧会话没有该字段时最多读取64条同类记录折叠，后续以最新结构化状态递增，不重复加载无限全文。

`assistant.compute → execute_search → retrieval_service.search`
使用effective_query及显式concepts/modality/excluded_modalities检索。明确“这些/其中/所选”时
限定到选中或上轮候选版本ID，版本权限重新查询。新的独立需求不误受之前选择卡片限制。

`retrieval_service → evidence_matches`
在当前元数据上检查支持的语义条件，两条通道（向量结果及词法补足）都检查，不能从补足路径绕过。
没有支持证据就不给出满足条件的版本卡片。常见否定不能可靠转换时保留原文并要求澄清，不偷偷删除条件。

## 压缩与权限

本次采用确定性的结构化任务摘要，不是让模型自由生成长期记忆。保存目标、模态、排除项、
少量附加要求、候选ID和近期用户请求。近期原文有字符上限，结构化已识别条件跨轮保留，摘要总量受限。
支持40轮以上连续追问；这不代表每轮所有全文都会进入模型。

未知附加要求只保留有界数量，超预算时明确要求集中描述/重置，避免默默丢弃需求。
原始聊天记录仍按原有保留/清除策略管理；清除对话后不再从被清除内容重建需求。
记忆只记用户需求，不记授权结论、质量“已通过”等实时事实，也不赋予自动审批或确认执行能力。
用户被禁用、会话失效、项目/组织权限变化仍由原有鉴权和每次检索二次校验处理。

目前主要内置老人/儿童及常见服饰条件，不是完整的任意自然语言逻辑解析器。
不支持跨会话自动保存个人偏好，也不将知识文档原文变成可信系统指令。

## 学习入口

- backend/app/agent_query_memory.py：refine做条件更新，prepare读取有界状态，evidence_matches检查来源支持。
- backend/app/assistant.py：准备上下文、执行检索、保存query_memory、返回tool供前端决定收藏能力。
- backend/app/retrieval_service.py：当前元数据验证、模态排除、多版本限定。
- frontend/src/pages/agent.tsx：自动摘要展示、收藏与普通选择版本分开。
- backend/tests/test_agent_query_memory.py：跨40轮、增删条件、否定澄清、无关候选拒绝、收藏和账号隔离。

无需数据库迁移，复用已有对话/运行表。数据集、文件和标注记录没有因本功能被修改。

## 人物组合条件补充

后续修正了“男性＋不戴帽子”被错误拦截为待澄清的问题，支持male/female与no_hat，
并从已独立复核的目标标签检索。入口在 `annotation_search.candidates`。

- 同一ImageReviewItem同时匹配所有条件，不能把甲的性别与乙的帽子拼起来。
- 目标和整图都必须审核通过且由不同账号编辑/复核；排除弃用批次、已排除重复图和评测真值。
- 仅在当前版本内容授权有效时返回数量，聊天历史也保存content权限引用，撤权后隐藏结果。
- 缺失、unclear、尚未复核不等于no_hat。
- 当前映射：人物类别person/human或旧人物类别，gender/sex对应male/female，hat对应hat/no_hat。
  自定义模板请使用稳定字段；任意别名不自动视为相同语义。
- 默认旧人物模板仅有hat、sleeve、upper_color，原视觉提示不推断性别。本次检索不会自动
  修改这些标签，也不会把原有预测直接标记为人工通过。

若需要新增性别标签，应在可编辑新版本配置person类别和gender字段（male/female/unclear），
导入合法来源标签或按明确业务规范标注并独立复核。已有识别记录的版本不能直接换模板。
当前实例的已审核标注尚无gender/sex字段，因此此组合条件不能返回已核验结果。
41项后端专项/回归、前端构建、MySQL只读属性查询通过，修复版已同数据库版本部署。
